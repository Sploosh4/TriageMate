## Item 1 — Pre-Tier RF: Tests + Feature Parity + Model Registry

**Assigned to:** strike  
**Type:** Code (test files + registry file)  
**Scope boundary:** Pre-Tier RF model only. No changes to the model itself, training pipeline, or inference logic.

### Deliverables

#### A. Unit tests — `backend/tests/test_pretier_features.py`
Test `pretier_features.py` — the shared feature extraction module used by both training and inference:
- `extract_features()` returns correct dict for known hostname patterns (health.wa.gov.au → agency_health=1)
- `feature_vector_to_array()` produces exactly 60 elements
- `get_feature_names()` returns 60 unique, deterministic names
- Edge cases: empty hostname, unusual patterns, no recognizable agency/role
- Verify index 59 is `system_category` (ordinal 0-8)

#### B. Unit tests — `backend/tests/test_pre_tier.py`
Test `pipeline/pre_tier.py` — the inference pipeline:
- `predict_mission_tags()` returns dict with expected keys (`mission_prevalence`, `public_wellbeing_impact`, `internet_facing`, `data_classification`, `confidence`)
- KNOWN_TAGS dict returns correct tags for known demo hostnames
- ML fallback works (mock `joblib.load` for the model)
- Default fallback works when model loading fails
- Confidence score is in range [0, 1]

#### C. Feature parity guard — `backend/tests/test_feature_parity_pretier.py`
Verify the 60-dim feature vector contract:
- Training feature order (from `get_feature_names()`) matches inference feature order
- Same module is used for both paths (trivial, but formalize it)
- Test fails if a feature is added/removed/reordered without updating both sides

## Item 2 — EPSS Models: Tests + Feature Parity + Model Registry

**Assigned to:** strike  
**Type:** Code (test files + registry file)  
**Scope boundary:** EPSS v1-v4 fallback chain only. No changes to the models themselves, training pipelines, or substitution logic.

### Deliverables

#### A. Unit tests — `backend/tests/test_epss_substitutor.py`
Test `epss_substitutor.py` — the fallback chain and substitution engine:
- `calculate_substitution()` returns expected structure (`result`, `substituted`, `confidence`, `version`)
- Fallback chain loads successfully: v4 → v3 → v2 → v1 → rule_engine
- `_rule_engine()` heuristic fallback produces deterministic output for known inputs
- Module-level load doesn't crash when some model files are missing
- Edge cases: missing CVE ID, missing hostname, unknown agency

**Note:** These tests work with the actual model files on disk. Don't mock the model loading unless it causes import errors.

#### B. Feature parity guard — `backend/tests/test_feature_parity_epss.py`
Verify the 37-dim feature vector contract:
- CRITICAL: `_build_feature_vector_v2()` in `train_epss_v4.py` and `epss_substitutor.py` are SEPARATE implementations. For the same inputs (CVE ID, hostname, CVSS score, EPSS score, KEV status), verify both produce the same 37-element feature vector.
- Test with concrete examples: known CVE IDs, known agency hostnames
- If they DON'T match, document the divergence precisely (index, expected value, actual value)
- If they DO match, formalize it as a contract test

**Assumption:** The feature vectors may NOT be perfectly aligned. If divergence is found, fix the inference side to match the training side (training is source of truth).

## Item 3 — Quality Gate Loop

**Condition:** After Items 1 and 2 are implemented  
**Process:** Run until two consecutive passes return nothing

1. **Test** — `just test` (all tests must pass, including new ones)
2. **Lint** — `just lint`
3. **Graphify** — `just graphify` (regenerate auto-docs)
4. **Audit** — `just audit-all` (calibration, parity, EPSS, schema) — delegate to auditor
5. **Bookkeeper** — delegate to bookkeeper for a freshness pass
6. If any issues found → fix → re-run steps 1-5
7. Repeat until two consecutive clean passes
