## Item 1 — Fix CIA default mismatch in parity check script

**Bug:** `analysis/feature_parity_check.py` `build_inference_vector()` defaults missing CIA values to 2.0, but the actual inference code (`ingest_helpers.py`) defaults to 0 (via `_cvss_cia(cvss_vec.get("C", "N"))` where `_cvss_cia("N")` = 0). This creates a false positive drift detection.

**Fix:** Change lines 399-401 from:
```python
cvss_c = 2.0 if cvss_vec.get("C") is None else float(_cvss_cia(cvss_vec["C"]))
```
to match the actual inference pattern:
```python
cvss_c = float(_cvss_cia(cvss_vec.get("C", "N")))
```
Same for I (line 400) and A (line 401).

Also update the comment on line 393 that says "inference defaults" to reflect the correct behavior.

## Item 2 — Fix lateral_reachability type mismatch

**Bug:** Training (`train_xgboost.py` `_compute_lateral_reachability`) returns binary 0/1. Inference (`ingest_helpers.py` `_synthetic_lateral`) returns counts 3-20. Model learned binary boundary but receives counts.

**Fix:** Binarize the inference value in `ingest_helpers.py` line 464:
Change:
```python
"lateral_reachability": _synthetic_lateral(asset_ctx),
```

To:
```python
"lateral_reachability": min(1, _synthetic_lateral(asset_ctx)),
```
