## Architecture Rules for Shared Config (Item 1)

> These rules govern where constants live and MUST be documented in the config module README/docstring.

### Centralize (belongs in a domain config file)
- **Magic numbers for business logic** — values that dictate routing, scoring, or ML behavior and need regular tuning (e.g., EPSS thresholds, CWE-stratified thresholds, scoring dimension weights, NVD ref threshold, drift PSI thresholds)
- **Variables shared across 2+ modules** — if `xgboost_predictor.py` and `tier_0.py` both read the same CWE threshold, it goes in config

### Keep local (leave at the top of the file)
- **Single-file constants** — if a constant is used in exactly one function or one file (e.g., `MAX_RETRIES = 3` in an API fetcher, a formatting string, a feature encoding mapping used only in inference), leave it at the top of that file
- Moving single-use constants to a global config forces you to jump between files to understand a single function — that's worse than duplication

### Config module structure

```
backend/pipeline/config/
  __init__.py           # imports and re-exports all sub-modules
  thresholds.py         # CWE_EPSS_THRESHOLDS, KEV/CVSS thresholds, NVD_REF_THRESHOLD, drift PSI thresholds
  scoring.py            # SCORING_DIMENSIONS dict with weights, max values, clamping bounds
  feature_names.py      # TABULAR_FEATURE_ORDER (35), Pre-Tier feature names (60), EPSS feature names (37/22)
  training.py           # training-only constants (batch sizes, random seeds, CV folds)
  __init__.py pattern:  # from .thresholds import *  (explicit __all__ in each)
```

## Item 2: Scheduled Retraining Triggers

**Effort:** ~4-5 hrs | **Assignee:** strike | **Priority:** High

### What
Extend `backend/scheduler.py` to trigger model retraining when:
- **Drift-triggered:** Composite PSI crosses warning (0.10) or critical (0.25) thresholds — detected by polling `GET /api/drift/ml`, `/api/drift/epss`, `/api/drift/pre-tier`
- **Time-triggered:** Periodic schedule (weekly by default, configurable via env var)

### Why
Sprint 18 added drift detection endpoints. But drift detection without action is just observability. Retraining triggers close the loop: detect drift → retrain → validate → deploy.

### Implementation

1. **Extend `backend/scheduler.py`:**

   a. **Add retraining check function:**
      ```python
      async def check_drift_and_retrain():
          """
          Poll drift endpoints. If any model has PSI >= DRIFT_WARNING_PSI,
          trigger retraining for that model. Runs on schedule (default: weekly).
          """
      ```

   b. **Add retraining execution:**
      ```python
      async def retrain_model(model_name: str) -> dict:
          """
          Execute retraining pipeline for a specific model.
          
          Args:
              model_name: "xgboost" | "pre_tier" | "epss_v4"
          
          Returns:
              dict with status, model_name, metrics, error (if any)
          
          Implementation:
              - Uses DIRECT FUNCTION IMPORT (not subprocess) to avoid CWD/venv/corruption issues
              - Imports training module and calls retrain() function directly
              - Capture return metrics (ROC-AUC, accuracy)
              - Compare new metrics against current active model in registry
              - Reject if new metrics are significantly worse (ROC-AUC drop >0.05)
              - Update registry and invalidate in-memory cache on success
              - Skips if a retrain is already in progress (lock file)
          """
      ```

   c. **Add drift polling:**
      ```python
      async def poll_drift_status() -> dict[str, float]:
          """
          Query drift API endpoints for composite PSI values.
          
          Returns:
              {"xgboost": 0.05, "pre_tier": 0.12, "epss": 0.03}
          """
      ```

   d. **Add config/env vars:**
      ```python
      RETRAIN_INTERVAL_HOURS = int(os.getenv("RETRAIN_INTERVAL_HOURS", "168"))  # 7 days
      RETRAIN_DRIFT_THRESHOLD = float(os.getenv("RETRAIN_DRIFT_THRESHOLD", "0.10"))  # warning level
      ```

   e. **Add scheduler registration** in `backend/main.py`:
      - Register `check_drift_and_retrain` with `RETRAIN_INTERVAL_HOURS` interval
      - ADD `apscheduler` to `requirements.txt` (required, not currently installed)
      - Use APScheduler for cron-based scheduling
      - Log: "Retraining scheduler registered (interval={RETRAIN_INTERVAL_HOURS}h, drift_threshold={RETRAIN_DRIFT_THRESHOLD})"

2. **Add lock mechanism** — prevent concurrent retrains:
   - Use file lock at `backend/ml/.retrain.lock`
   - Check before starting; skip if lock exists and is < 6 hours old (staleness guard)
   - Remove lock on completion or failure

3. **Add drift endpoint for internal polling** (if no HTTP call needed):
   - Alternative: directly import and call drift computation + retraining logic
   - **Decision:** Use direct function calls (no HTTP loopback) to avoid circular dependency. Import from `analysis.drift` and call `compute_drift()` directly.

4. **Add API status endpoint:**
   - `GET /api/system/retrain-status` — returns:
     ```json
     {
       "last_retrain": "2026-07-10T03:00:00Z",
       "last_drift_check": "2026-07-10T10:30:00Z",
       "drift_status": {"xgboost": 0.05, "pre_tier": 0.12, "epss": 0.03},
       "lock_held": false
     }
     ```

5. **Add logging** — structured logs for:
   - "Drift check: XGBoost PSI=0.12 (warning), Pre-Tier PSI=0.05 (stable)"
   - "Retrain triggered: pre_tier (drift=0.12, threshold=0.10)"
   - "Retrain completed: pre_tier (ROC-AUC=0.942, previous=0.946)"
   - "Retrain skipped: lock held (age=2h)"

### Acceptance Criteria
- `check_drift_and_retrain()` function exists and is testable
- Lock mechanism prevents concurrent retrains
- `GET /api/system/retrain-status` returns valid JSON

## Item 4: Concept Drift — Prediction Distribution + Ground-Truth Feedback

**Effort:** ~4-5 hrs | **Assignee:** strike | **Priority:** Medium

### What
Add prediction-level drift monitoring:
- **Part A (Prediction distribution tracking):** Track the distribution of model outputs (exploitation_probability, confidence, routing decisions) over time windows via `/api/drift/concept` endpoint
- **Part B (Ground-truth feedback loop foundation — API stubs only, no DB schema changes):** Add infrastructure to collect and store prediction outcomes when ground truth becomes available. Schema changes deferred to Sprint 20.

### Why
PSI drift (Items 3-4 of Sprint 18) detects feature distribution shifts. ### Bonus G: Model Registry Rollback API

**Effort:** ~2 hrs | **Priority:** Low

**What:** API endpoint to rollback XGBoost model to a previous version.

**Why:** If a new model version degrades prediction quality, rollback should be fast and safe — no file shuffling, no server restart.

**Implementation:**

1. **Endpoint:** `POST /api/models/xgboost/rollback?version=<version_tag>`:
   ```python
   @router.post("/api/models/xgboost/rollback")
   def rollback_xgboost(version: str = Query(...)):
       """Rollback XGBoost model to a previous registry version.
       
       Steps:
       1. Validate version exists in model_registry.json
       2. Update active_version in registry
       3. Call set_active_version() to invalidate in-memory cache
       4. Return new active version info
       """
   ```

2. **Validation:**
   - Version must exist in registry
   - Version must not be the currently active one (no-op)
   - Version must have valid model_file path on disk

3. **Response:**
   ```json
   {
     "status": "success",
     "previous_version": "v3",
     "active_version": "v2",
     "model_file": "xgboost_model_v2.pkl",
     "metrics": {"roc_auc": 0.942, "accuracy": 0.88}
   }
   ```

4. **Test safety:**
   - No concurrent rollback (lock)
   - If `set_active_version()` fails, restore previous version
   - Log: "Model rolled back: v3 → v2 (trigger: API call by admin)"

**Tests:**
| Test | What it verifies |
|------|-----------------|
| `test_rollback_valid_version()` | Success for existing version |
| `test_rollback_nonexistent_version()` | 404 for missing version |
| `test_rollback_same_version()` | 400 for already active version |
| `test_rollback_clears_cache()` | In-memory model cache invalidated |
| `test_rollback_no_concurrent()` | Second call while first in progress → 409 |
