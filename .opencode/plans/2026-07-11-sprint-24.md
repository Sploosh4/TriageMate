## Executive Summary

This sprint transforms the TriageMate project to use GitHub Issues, Milestones, and Labels for AI-accessible work tracking, while keeping documentation in the local `docs/` tree. The local `.md` file system (sprint plans at `.opencode/plans/`) is migrated to GitHub-native work tracking — Issues, Labels, Milestones, and Issue Templates.

**Design principle (work tracking):** Every feature chosen is optimised for AI agent accessibility. The ranking was:
| Feature | AI Value | Included? |
|---|---|---|
| Issues + Custom Labels | 🥇 API-filterable, searchable work items | ✅ |
| Milestones | 🥇 Temporal grouping for AI queries | ✅ |
| Issue Templates | 🥇 YAML frontmatter = structured data for AI parsing | ✅ |
| Wiki | 🥇 Separate git repo, fully API-accessible docs | 🟡 Deferred — see note below |
| Projects Board | 🥉 GraphQL-accessible status visibility | ❌ Deferred — Labels+Milestones suffice for AI |
| Repo metadata (description + topics) | ✅ Bonus — quick-win metadata | ✅ |
| Discussions | ❌ GraphQL-only, lower ROI | ❌ Skip |
| Releases | ❌ Not needed until versioned release | ❌ Skip |
| PR Templates | ❌ Solo AI dev, low priority | ❌ Skip |

**Why Wiki is deferred:** The critical review found that local `.md` files are equally AI-accessible (both are markdown in git repos). Wiki adds auth/network overhead for no AI gain. Wiki migration is deferred to a future sprint or stretch goal. The `docs/` directory remains the canonical doc source for now, with structural improvements made in this sprint.

### Idempotency Pattern

All `gh` operations in this phase MUST follow this pattern:
```bash
# Check if resource exists before creating
safe_create_label() {
  local name="$1" color="$2" desc="$3"
  if gh label list --json name | jq -e ".[] | select(.name == \"$name\")" > /dev/null 2>&1; then
    echo "Label '$name' already exists — skipping"
  else
    gh label create "$name" --color "$color" --description "$desc"
    echo "Created label: $name"
  fi
}

safe_create_milestone() {
  local title="$1" state="$2" desc="$3"
  if gh api "repos/Sploosh4/TriageMate/milestones?state=all" --jq '.[].title' | grep -q "^${title}$"; then
    echo "Milestone '$title' already exists — skipping"
  else
    gh api -X POST repos/Sploosh4/TriageMate/milestones \
      -f title="$title" -f state="$state" -f description="$desc"
    echo "Created milestone: $title"
  fi
}
```

### Cleanup Procedure (if rollback needed)

To undo all remote API changes:
```bash
# Delete all created issues (close them — GitHub API cannot delete issues)
for id in $(jq -r '.issues[]' "$MANIFEST"); do
  gh api -X PATCH repos/Sploosh4/TriageMate/issues/$id -f state=closed
done

# Delete all created labels (the 15 custom labels created in Phase 1)
for name in task research priority-p0 priority-p1 priority-p2 priority-p3 area-scoring area-pipeline area-frontend area-ml area-docs area-infra area-api status-blocked status-needs-review status-in-progress; do
  gh label delete "$name" --yes 2>/dev/null || echo "Label '$name' not found — skipping"
done

# Delete all created milestones
for title in $(jq -r '.milestones[]' "$MANIFEST"); do
  number=$(gh api "repos/Sploosh4/TriageMate/milestones?state=all" --jq ".[] | select(.title==\"$title\") | .number")
  if [ -n "$number" ]; then
    gh api -X DELETE repos/Sploosh4/TriageMate/milestones/$number
  fi
done
```

## Risk Register

| Risk | Likelihood | Impact | Mitigation |
|------|-----------|--------|------------|
| 🔴 GitHub API rate limits (5,000 req/hr) | Low | High | Batch operations. Create issues in groups of 10 with 1-second pauses. Most operations are single-call. |
| 🟡 gh label create fails for duplicates | Medium | Low | Default labels already exist (bug, enhancement, documentation). Script should check before creating or handle errors gracefully. |
| 🟡 gh milestone create — `gh` has no direct `milestone` command | Medium | Low | Use `gh api` to POST milestones. Well-documented API. |
| 🟡 issue templates config.yml misconfiguration | Low | Medium | Test template preview URL before committing. |
| 🟢 Issue templates don't show up immediately | Low | Low | GitHub caches template config for a few minutes. Not critical. |
| 🟢 `just graphify` produces unexpected output from archive dir | Low | Medium | Review diff before committing. Archive is at `archive/` (project root, outside `docs/`), unlikely to affect graphify. |
| 🟡 Symlinks broken by archive directory creation | Low | Medium | Validate symlinks early in Phase 3 (Item 3.5) before commit. |
