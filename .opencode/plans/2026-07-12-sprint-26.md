# Sprint 26 — Feature Contract Enforcement

**Date:** 2026-07-12
**Theme:** Make the 35-column Tier 1 tabular feature contract authoritative, mechanically enforced, and visible in CI.

---

## Objective and boundaries

Prevent training/serving feature-order and missing-value drift for the Tier 1 XGBoost model. The authoritative contract is `pipeline/config/feature_names.py::TABULAR_FEATURE_ORDER` (35 names in positional order).

This sprint is limited to the Tier 1 tabular contract. It does not redesign the synthetic asset-context features, change model labels, change scoring, add a new feature, or claim that the graphify AST report can infer runtime semantics. PCA/SBERT names and the Pre-Tier/EPSS contracts are out of scope.

### Verified current state

- `xgboost_predictor.py` consumes `TABULAR_FEATURE_ORDER`, but its fallback defaults are local.
- `train_xgboost.py` imports the canonical list only when saving NPZ metadata; `build_tabular_features()` still writes to literal indices `0..34`.
- `build_training_corpus.py`, `ingest_helpers.py`, `feature_parity_check.py`, and `test_feature_parity.py` each maintain a second, hand-written 35-name list.
- The corpus builder writes `training_data_v2.npz`; `train_xgboost.py --train` consumes `training_data.npz`. Rebuilding v2 alone therefore does **not** update the model currently loaded by inference.
- `ingest_helpers._cvss_cia()` and predictor fallbacks use High (`2`) for an absent/malformed CIA component, while training maps absent CIA components to None (`0`).
- `train_xgboost.py` writes `reference_count` into newly gathered cached CVEs and reads it at feature index 23, though the canonical name is `nvd_reference_count`.
- `ingest_helpers.build_feature_vector()` returns 46 keys: 35 tabular inputs, 10 metadata/enrichment values, and `description`. Its docstring incorrectly says 42 keys and names a nonexistent `osv_lead_days` output.
- Existing `test_feature_parity.py` has useful coverage but creates another key-list source of truth and does not call `_build_tabular_array()`.
- The regular GitHub CI test step already runs `pytest tests/`; a separately duplicated pytest step is unnecessary.

### Success criteria

| Criterion | Definition of done |
|---|---|
| One feature-name authority | Production code and feature-contract tests import `TABULAR_FEATURE_ORDER`; no duplicate 35-name constants remain in the Tier 1 paths listed above. |
| Safe fallback semantics | Missing/malformed CIA values map to `0`; absent patch/domain values use explicit, documented defaults that match the NVD and hostname adapters. |
| Backward-compatible cache migration | New gathered CVEs use `nvd_reference_count`; cached legacy `reference_count` is still readable. |
| Executable contract tests | Tests exercise the real inference array builder and deterministic training/corpus outputs without network, SBERT, a model artifact, or a live app. |
| CI enforcement | `just check-feature-contract` and the existing CI test job fail on a contract violation. |
| Artifact integrity | The deployed model is retrained only when its actual input artifact changes; its feature count/names and ROC-AUC guardrail are verified before replacement. |

## Phase 1 — Establish a single executable contract

### 1.1 Extend the canonical module deliberately

**File:** `backend/pipeline/config/feature_names.py`

Keep `TABULAR_FEATURE_ORDER` as the only Tier 1 name/order list. Add small, typed contract constants only where they eliminate real duplication, for example:

- `TABULAR_FEATURE_COUNT = len(TABULAR_FEATURE_ORDER)`;
- `TABULAR_METADATA_KEYS` for the non-model keys returned by `build_feature_vector()`;
- `TABULAR_TEXT_FEATURE_PREFIX` or reuse `make_sbert_feature_names()` consistently.

Do **not** move training’s synthetic-distribution logic into generic predictor defaults. Training and inference deliberately obtain several asset-context values differently; the contract is schema/order/type compatibility, not equality of their simulated values.

### 1.2 Remove duplicate feature-name constants

Replace local Tier 1 lists with imports from the canonical module in:

- `backend/scripts/build_training_corpus.py` (`_FEATURE_NAMES`);
- `backend/ingest_helpers.py` (the list used by `prepare_xgboost_features()`);
- `backend/analysis/feature_parity_check.py` (`FEATURE_NAMES`);
- `backend/tests/test_feature_parity.py` (`PREDICTOR_TABULAR_KEYS`).

Use the canonical count rather than literal `35` where it describes the contract. Literal index assignments in legacy builders may remain only if a test maps every index to the canonical name; prefer a named mapping or an ordered row assembled from canonical keys when that is a small, reviewable refactor.

Update the corpus builder’s saved `feature_names` and `columns` from the canonical list. Use `make_sbert_feature_names()` where the saved model artifact uses its naming convention; preserve existing `text_sbert_*` naming only if changing it would invalidate a current consumer, and document that compatibility choice in the implementation.

### 1.3 Correct explicit missing-value behaviour

**CIA:** Change all three relevant `_cvss_cia()` fallbacks—ingest helper, predictor-equivalent parity code, and both corpus/training parsers if needed after inspection—to `0` for absent or malformed components. Add a direct unit test for `None`, empty, and invalid values.

**Patch availability:** `integrations/nvd.get_nvd_data()` already returns `False` when data is unavailable. Align `ingest_helpers.build_feature_vector()` and predictor fallback with that adapter (`False`), then verify known seed rows still pass their actual patch value. Do not justify a default by an unverified corpus percentage.

**Domain joined:** retain `False` for a missing feature because `_derive_domain_joined()` returns false for unknown/OT hostnames. Change the predictor and parity-check fallbacks accordingly. This is a missing-data policy, not an assertion that generated training data must be false.

Centralise only defaults shared by runtime ingestion, prediction, and the parity diagnostic. If a shared mapping would make the code clearer, add it to a narrow feature-contract module; otherwise keep a single explicit helper and import it. Do not leave three copied fallback dictionaries.

### 1.4 Migrate `reference_count` safely

**File:** `backend/ml/train_xgboost.py`

- Write `nvd_reference_count` for newly gathered CVEs.
- Read `cve.get("nvd_reference_count", cve.get("reference_count", 0))` at index 23, so old cached files work.
- Add a focused regression test covering both keys and the canonical-index location.

### 1.5 Fix feature-vector documentation

Correct the `build_feature_vector()` docstring to state the actual 46 keys: 35 tabular, 10 metadata/enrichment, and one text key. Remove `osv_lead_days`; it belongs to the offline corpus metadata, not the runtime feature dict. Derive the stated count from the contract constants where practical so the prose cannot drift again.

**Phase 1 exit condition:** no listed Tier 1 path has its own 35-name constant; the modified defaults have direct tests; formatting and targeted tests pass.

## Phase 2 — Deterministic, behaviour-based tests

**New file:** `backend/tests/test_feature_contract.py`

Tests must not download SBERT, load a real XGBoost artifact, require an NPZ file, call a live adapter, or use a permanently skipped test as a deliverable.

1. `test_tabular_registry_is_unique_and_expected_size`
   - Assert uniqueness and the deliberate expected count (35), with an error explaining that schema changes require all producers/consumers to be updated.

2. `test_runtime_feature_vector_has_exact_tabular_and_metadata_contract`
   - Mock adapters and build a real runtime feature dict.
   - Assert its tabular-key subset equals the canonical list, and its non-tabular keys equal the documented metadata/text contract. This replaces the loose `len(fv) >= 40` assertion.

3. `test_predictor_builds_values_in_canonical_order`
   - Call the real `_build_tabular_array()` using distinctive values for each feature plus known categorical values.
   - Assert each position corresponds to `TABULAR_FEATURE_ORDER`. This catches ordering drift that a shape-only test misses.

4. `test_missing_value_policy_is_explicit`
   - Exercise CIA, patch availability, and domain-joined absence through the real runtime and predictor paths.
   - Assert only documented defaults; do not compare against randomly sampled training fields.

5. `test_training_builders_emit_canonical_width_and_saved_names`
   - Supply a minimal synthetic corpus to each builder with deterministic random functions patched or seeded.
   - Assert 35 tabular columns and that the saved NPZ metadata begins with the canonical list. Use `tmp_path`; never depend on a gitignored large artifact.

6. `test_legacy_reference_count_is_supported`
   - Verify both cache spellings yield the same feature value at `nvd_reference_count`’s canonical index, and that new gather output uses only the canonical spelling.

Refactor existing `test_feature_parity.py` rather than layering duplicate assertions on top of it: import the canonical list, call the real predictor builder, remove its meta-test that only mutates a local list, and update NPZ text-name expectations to the approved naming convention.

**Phase 2 exit condition:** every test is deterministic, meaningful in CI, and fails with the feature name, expected contract, and primary correction path.

## Phase 3 — Diagnostics and quality gates

### 3.1 Improve, do not overpromise, the parity diagnostic

Make `feature_parity_check.py` import the registry and shared default policy. Its report must distinguish:

- deterministic contract violations (non-zero exit);
- expected differences caused by synthetic/stochastic training context (reported separately, not a failure);
- unsupported/unavailable input data (clear diagnostic).

The diagnostic should return non-zero only for a genuine deterministic skew or schema/order violation. Avoid a target such as “graphify reports zero mismatches”: graphify analyses source structure and cannot prove runtime parity when a function returns metadata alongside model inputs.

### 3.2 Add one focused local recipe

**File:** `justfile`

Add `check-feature-contract`, running the new contract test file. Add it to `gate` after lint and before the full test suite. This is intentionally focused and quick; the full suite still provides integration coverage.

Retain `audit-features` as a diagnostic. If its exit behaviour is corrected in 3.1, include it in `gate` only once it is deterministic and network-independent; otherwise keep it outside the gate and document why.

### 3.3 Use the existing CI test step

Do not add a second raw pytest CI command: `.github/workflows/ci.yml` already runs all `backend/tests/` on Python 3.11 and 3.12. Confirm the new test runs there. Only change CI if a required environment marker, dependency, or path prevents that; make the smallest corresponding change.

**Phase 3 exit condition:** `just check-feature-contract` and `just gate` enforce the intended checks locally, and CI runs the tests exactly once per matrix environment.

## Phase 4 — Artifact decision, verification, and tracking

### 4.1 Model-artifact decision gate

The source fixes change only runtime fallbacks when a feature is absent, and a metadata key in the legacy trainer. They do not automatically justify retraining or replacing the deployed model.

Before retraining, determine which artifact inference uses and whether its training input values/order changed. Then:

- If only inference fallbacks, diagnostics, tests, and metadata changed: do **not** retrain; validate the existing artifact’s feature count and metadata compatibility.
- If the selected training corpus or feature construction changed: rebuild the exact corpus consumed by the training command, retrain in an isolated candidate path, verify feature names/count and ROC-AUC against the established guardrail (≥0.9359), then promote it only after those checks pass.
- Never overwrite the current model before candidate validation. Record data provenance, command, metric, and artifact version/rollback path.

### 4.2 Verification checklist

1. Run targeted contract and regression tests.
2. Run `just check-feature-contract`, `just test`, `just verify-seeds`, and `just gate`.
3. Run `just audit-features`; confirm its deterministic section is clean and inspect expected stochastic output.
4. Run `just graphify`; review the report for explanation accuracy rather than requiring an artificial zero mismatch count.
5. Inspect the final diff and confirm no generated model/corpus artifact is accidentally committed unless explicitly intended and allowed by repository policy.
6. Update the Sprint 26 roadmap/issue status only after evidence satisfies the criteria. GitHub Issues and Milestones remain canonical; because `gh auth status` is currently unauthenticated, use the commander’s authorised GitHub mechanism or obtain authentication before remote changes.
7. Delegate the required bookkeeper freshness pass. Address any real documentation drift it finds.

## Risks and controls

| Risk | Control |
|---|---|
| Treating synthetic training values as production defaults | Separate schema/default-policy tests from distributional parity diagnostics. |
| Retraining the wrong corpus/artifact | Require the artifact decision gate and candidate validation before promotion. |
| Tests pass while order drifts | Use distinctive-value tests against the real predictor builder, not shape-only checks. |
| Duplicate lists reappear | Import the registry in every listed path and code-review/search for new 35-name constants. |
| Generated artifacts or unrelated local work are overwritten | Record git state up front, use temporary paths for tests, inspect the final diff. |
| CI time/network flakiness | Keep contract tests adapter-mocked, artifact-free, and in the existing test command. |
