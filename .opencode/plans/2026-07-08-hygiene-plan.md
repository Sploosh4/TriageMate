## Phase C — Code Fixes (verify with tests after each)

### C1. Fix scoring dimension comment + patch dimension logic

**File:** `backend/scoring.py`

**Problem 1 — Weights sum to 107, not 100:**
```
CVSS 40 + EPSS 20 + criticality 20 + exposure 12 + patch 5 + ml_exploitation 10 = 107
```
Docstring says "0-100 score". Fully-loaded case hits 107 → clamped to 100, compressing the top of the scale.

**Fix options (pick one with user):**

| Option | Change | Effect |
|---|---|---|
| **C1a (minimal)** | Update docstring to note max possible is 107, clamped to 100 | Honest, no logic change |
| **C1b (rebalance)** | Reduce CVSS 40→35, exposure 12→10, patch 5→5, ml 10→10, epss 20→20, crit 20→20 = 100 | Clean 100 scale, but changes all scores — invalidates `[94,87,71,63,55,41,22]` baseline |
| **C1c (rebalance minor)** | Reduce exposure 12→10, ml 10→8 = 105 | Smaller shift |

**Recommendation (user-confirmed):** C1a — doc fix only. Rebalancing invalidates the Sprint NEXT+ Wave 1 score baseline `[94,87,71,63,55,41,22]` and the `test_scoring.py` 16 tests. Deferred to a dedicated scoring-calibration sprint.

**Problem 2 — Patch dimension conflates "no patch exists" with "patch overdue":**
```python
# Current:
if patch_available and not patch_applied: patch_score = 0   # overdue
elif patch_available and patch_applied:    patch_score = 5   # applied
# else (no patch available): falls through, patch_score = 0  ← same as overdue
```

**Fix:**
```python
if not patch_available:
    patch_score = 0  # no remediation available — neutral, not punitive
elif patch_available and patch_applied:
    patch_score = 5  # remediated
else:
    patch_score = 0  # patch exists but not applied — overdue (could escalate)
```

This is a logic clarification, not a score change (still 0 for no-patch). But it makes intent explicit and opens the door to awarding points for "no patch exists" if policy changes.

**Verify:** `just test-file test_scoring` — all 16 tests pass.

**Commit:** `fix: clarify scoring dimension weights and patch availability logic`

### C4. Plumb real LLM cost into verbose trace

**File:** `backend/routers/ingest.py:249-253`

**Problem:** Verbose trace hardcodes `tokens_in: 0, tokens_out: 0, cost_usd: 0.0` for Tier 2. Real cost lives in `tier_2._cost_tracking` (module-level accumulator) but isn't surfaced per-request.

**Fix:**
1. Have `evaluate_tier_2()` snapshot cost before/after the call and return delta:
   ```python
   # In pipeline/tier_2.py evaluate_tier_2():
   cost_before = get_cost_tracking()
   # ... call provider ...
   cost_after = get_cost_tracking()
   result["_cost_delta"] = {
       "tokens_in": cost_after["total_input_tokens"] - cost_before["total_input_tokens"],
       "tokens_out": cost_after["total_output_tokens"] - cost_before["total_output_tokens"],
       "cost_usd": round(cost_after["estimated_cost_usd"] - cost_before["estimated_cost_usd"], 6),
   ```

**Alternative (simpler, less invasive):** Have `call_openai`/`call_anthropic`/`call_together` return `(result, usage_dict)` tuples, and have `evaluate_tier_2` attach usage to the result dict. Skip the snapshot-diff approach.
