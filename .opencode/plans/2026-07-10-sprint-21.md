### What

Replace the additive Security Context dimension with a proportional multiplier. The multiplier scales the total score based on security context evidence:

| Condition | Multiplier | Effect |
|-----------|-----------|--------|
| Active threat detected AND vulnerable code loaded | 1.20 | Score increases 20% |
| Active threat detected OR vulnerable code loaded (one but not both) | 1.10 | Score increases 10% |
| No threat evidence, code status unknown | 1.00 | Neutral — no change |
| Confirmed mitigated / code not loaded | 0.85 | Score decreases 15% |
| Confirmed false positive / irrelevant | 0.70 | Score decreases 30% |

**Why this specific scale?**
- **1.20** reflects a genuine active-compromise scenario — the vulnerability is being actively exploited AND the vulnerable code is loaded on the asset. This is the most urgent case and gets the largest uplift.
- **1.10** for partial evidence — one signal but not both. Still elevated, but not as urgent.
- **1.00** neutral — default when no telemetry is available. No penalty for missing data.
- **0.85** for confirmed mitigation (patched, workaround applied, or vulnerable code not deployed). This is a meaningful but not extreme reduction.
- **0.70** for confirmed false positive or irrelevant — the CVE doesn't apply to this asset. This is a strong reduction.

#### Order of Operations (Critical Design Decision)

```
base_dimensions_sum → apply multiplier → apply Tier 2 adjustment → clamp to 0-100
```

Rationale:
- The multiplier reflects deterministic environmental context (telemetry, network)
- The Tier 2 adjustment reflects LLM-based semantic analysis
- The LLM should have the final say (±20 adjustment) on top of the context-adjusted score
- This means: `total = round((pre_adjustment_sum * multiplier) + tier_2_adjustment)`

**Assumption:** The commander recommends multiplier BEFORE Tier 2 adjustment. If the user disagrees, the change is a single line — move the multiplier application after the Tier 2 addition.

#### 1B. Implement multiplier determination logic (~2 hrs)

Create a new function in `backend/scoring.py`:

```python
# Context multiplier configuration
CONTEXT_MULTIPLIERS = {
    "active_threat_loaded": 1.20,
    "partial_evidence": 1.10,
    "neutral": 1.00,
    "mitigated": 0.85,
    "false_positive": 0.70,
}

# Threshold for considering a telemetry score as "active threat"
# Configurable via pipeline/config/scoring.py
TELEMETRY_ACTIVE_THRESHOLD = 3.0  # On a 0-10 threat score scale. 0.0 would
                                  # cause any noise to trigger "active threat".
                                  # 3.0 requires meaningful evidence.


def _determine_context_multiplier(
    telemetry_threat_score: float,
    vulnerable_code_loaded: bool | None = None,
    confirmed_mitigated: bool = False,
    confirmed_false_positive: bool = False,
) -> float:
    """Determine the security context multiplier based on telemetry and network evidence.
    
    Returns one of: 1.20, 1.10, 1.00, 0.85, 0.70
    
    Decision matrix:
    - confirmed_false_positive=True → 0.70 (strongest reduction — CVE doesn't apply)
    - confirmed_mitigated=True → 0.85 (meaningful reduction — risk addressed)
    - telemetry_threat_score >= TELEMETRY_ACTIVE_THRESHOLD AND vulnerable_code_loaded=True → 1.20
    - telemetry_threat_score >= TELEMETRY_ACTIVE_THRESHOLD XOR vulnerable_code_loaded=True → 1.10
    - telemetry_threat_score < TELEMETRY_ACTIVE_THRESHOLD AND vulnerable_code_loaded is None/False → 1.00
    - default → 1.00 (neutral, no penalty for missing data)
    
    Note: network_blast_radius was considered but removed from the initial multiplier
    model because (1) it is a static property of the network zone, not dynamic threat
    evidence, and (2) blast radius is already factored into the Exposure dimension and
    the overall scoring model. If future analysis shows blast radius has additional
    predictive power beyond what's already captured, it can be re-introduced.
    
    The exact threshold for "active threat" (TELEMETRY_ACTIVE_THRESHOLD) is configurable
    via pipeline/config/scoring.py.
    """
    # False positive takes highest precedence
    if confirmed_false_positive:
        return CONTEXT_MULTIPLIERS["false_positive"]
    
    # Confirmed mitigation takes next precedence
    if confirmed_mitigated:
        return CONTEXT_MULTIPLIERS["mitigated"]
    
    # Active threat detection
    has_active_threat = telemetry_threat_score > TELEMETRY_ACTIVE_THRESHOLD
    has_loaded_code = vulnerable_code_loaded is True
    
    if has_active_threat and has_loaded_code:
        return CONTEXT_MULTIPLIERS["active_threat_loaded"]
    
    if has_active_threat or has_loaded_code:
        return CONTEXT_MULTIPLIERS["partial_evidence"]
    
    # Default: neutral
    return CONTEXT_MULTIPLIERS["neutral"]
```

2. **Add webhook function in `backend/analysis/drift.py`:**

```python
import httpx
import asyncio
from datetime import datetime, timezone

# In-memory suppression: {model_name: last_fired_psi_level}
_last_webhook_fired: dict[str, tuple[float, datetime]] = {}
WEBHOOK_SUPPRESSION_HOURS = 6


async def send_drift_webhook(
    model_name: str,
    psi_value: float,
    threshold: float,
    details: dict | None = None,
) -> bool:
    """POST drift alert to configured webhook URL.
    
    Payload:
    {
        "event": "drift_detected",
        "model": "xgboost",
        "psi": 0.12,
        "threshold": 0.10,
        "severity": "warning",
        "timestamp": "2026-07-10T12:00:00Z",
        "details": { ... }
    }
    
    Returns True if webhook was sent, False if suppressed or no URL configured.
    """
    url = os.getenv("TRIAGEMATE_DRIFT_WEBHOOK_URL", "")
    if not url:
        return False
    
    # Suppression check: same model + same PSI level within 6 hours
    now = datetime.now(timezone.utc)
    psi_level = "warning" if psi_value < 0.25 else "critical"
    last_fired = _last_webhook_fired.get(model_name)
    if last_fired:
        last_psi_level = "warning" if last_fired[0] < 0.25 else "critical"
        hours_since = (now - last_fired[1]).total_seconds() / 3600
        if last_psi_level == psi_level and hours_since < WEBHOOK_SUPPRESSION_HOURS:
            logger.debug("Drift webhook suppressed for %s (%s, %.1fh since last)", 
                         model_name, psi_level, hours_since)
            return False
    
    payload = {
        "event": "drift_detected",
        "model": model_name,
        "psi": psi_value,
        "threshold": threshold,
        "severity": psi_level,
        "timestamp": now.isoformat(),
        "details": details or {},
    }
    
    try:
        async with httpx.AsyncClient(timeout=10.0) as client:
            resp = await client.post(url, json=payload)
            resp.raise_for_status()
        
        _last_webhook_fired[model_name] = (psi_value, now)
        logger.info("Drift webhook sent: %s PSI=%.3f (%s)", model_name, psi_value, psi_level)
        return True
    except Exception as e:
        logger.error("Drift webhook failed for %s: %s", model_name, e)
        return False
```
