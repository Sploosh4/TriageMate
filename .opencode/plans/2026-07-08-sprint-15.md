### Item 3 — Stress Testing + Visibility

**Subagent:** strike (backend-engineering + devops-engineering)
**Execution order:** Third (validates Items 1+2 under load)

**LLM provider:** OpenAI `gpt-4o-mini` (existing config). DeepSeek deferred to future sprint.

**Deliverables:**

| Step | What | Lines |
|---|---|---|
| 3a | **Pipeline timing** — `time.monotonic()` around each tier in `routers/ingest.py`, collect per-tier latency in trace dict | ~30 |
| 3b | **Verbose response mode** — `X-TriageMate-Verbose: true` header triggers `_trace` field in ingest response, containing per-tier outputs + latency | ~50 |
| 3c | **Test DB module** — `backend/analysis/stress_db.py`: `create_db(path)`, `insert_run()`, `insert_result()`. Schema: `test_runs` table + `results` table (12 indexed cols + JSON `trace`). No Alembic — created on-the-fly. | ~100 |
| 3d | **Locust test client** — `backend/tests/load/locustfile.py`: loads CVEs from NVD corpus (~50 real CVEs with known KEV/EPSS labels), generates random WA gov hostnames, mixed workload (ingest 60% + queue read 30% + health 10%), sends `X-TriageMate-Verbose` header, writes each result to test DB. Balanced CVE mix: ~20% KEV, ~30% very-low (CVSS < 4), ~50% ambiguous. | ~150 |
| 3e | **Post-test analysis script** — `backend/scripts/stress_report.py`: reads test DB, produces 7-section report: (1) Summary, (2) Tier Routing counts+%, (3) Accuracy — KEV recall, score separation, low-severity precision, (4) Latency p50/p95/p99 per tier, (5) LLM Cost — calls/tokens/cost, (6) Risk Distribution histogram, (7) Failures breakdown. Outputs terminal + `backend/reports/stress/{run_id}.md`. | ~300 |
| 3f | **Docker hardening** — `WEB_CONCURRENCY` env var → `--workers` in Docker CMD (default 1), `mem_limit: 512m` + `cpus: 1.0` in docker-compose, `TRIAGEMATE_LLM_BASE_URL` env var support in `call_openai()` (future-proofs for non-OpenAI providers) | ~30 |
| 3g | **justfile orchestration** — `just stress-test`: start stack → wait for health → run locust 60s headless → run analysis → print report. `just stress-test-no-llm`: same with `TRIAGEMATE_LLM_API_KEY=""` override. | ~30 |
| 3h | **Locust installation** — add `locust` to `requirements-dev.txt` | ~1 |

**Test DB schema:**
```sql
CREATE TABLE test_runs (
    id TEXT PRIMARY KEY, started_at TEXT, ended_at TEXT,
    config JSON, total_requests INTEGER, successful INTEGER, failed INTEGER
);
CREATE TABLE results (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    test_run_id TEXT, seq INTEGER, ts TEXT,
    cve_id TEXT, hostname TEXT,
    status TEXT, priority_score INTEGER, risk_band TEXT,
    tier_0_routing TEXT, tier_1_routing TEXT, tier_2_called INTEGER,
    total_latency_ms REAL, llm_cost_usd REAL,
    trace JSON
);
```

**Analysis report sections:**
1. Summary — duration, requests, throughput, error rate
2. Tier Routing — count + % at T0 auto/escalated, T1 auto/escalated, T2 called, T3 flagged
3. Accuracy — KEV recall at T0, score separation KEV vs non-KEV, low-severity precision
4. Latency — p50/p95/p99 per tier + total
5. LLM Cost — calls, tokens in/out, estimated cost
6. Risk Distribution — band histogram, score histogram
7. Failures — error count, types, worst offenders

**Success metric:** `just stress-test` runs without errors. Locust report shows ingest throughput ≥ 0.3 RPS (18/min). Analysis report produces all 7 sections with non-zero, non-NaN values. Test DB is queryable.

**Verification tool:** `just stress-test` IS the verification. Plus `just stress-test-no-llm` for CI.

**Audit checkpoint ✅:** After strike completes, delegate to auditor. Verify:
- `just stress-test` completes without unhandled errors
- Test DB file exists and is queryable (spot-check SQL queries)
- Analysis report has all 7 sections with real values
- Verbose mode works: ingest with header returns `_trace` field
- No regression: all existing tests still pass
- Docker: `WEB_CONCURRENCY=2` starts 2 uvicorn workers
