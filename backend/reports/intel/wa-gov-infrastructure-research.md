### 4.3 Cloud Adoption (Australian Government)

Australian government cloud adoption follows these patterns:

- **Azure Australia regions:** Australia East (Sydney) - `aue`, Australia Central (Canberra) - `auc`. Canberra region is specifically designed for government/Protected workloads (certified by ASD).
- **AWS Australia regions:** ap-southeast-2 (Sydney) - `aue1`/`syd`
- **WA Government specific:** WA has a "cloud-first" policy (per WA Government Cloud Strategy). Agencies like WA Health use Azure for specific workloads, but legacy on-prem is still prevalent.
- **Protected cloud:** Azure Australia Central (Canberra) is the only region certified for Protected data under the PSPF.
- **Hybrid pattern:** WA government typically keeps sensitive/critical systems on-prem (domain controllers, SAP, health systems) while moving collaboration (Office 365) and web presence to cloud.

**Ref ID: NETWORK-003** — Cloud adoption patterns. Source: Microsoft Azure Australia documentation, ACSC cloud guidance.

### 4.4 Crown Network

The "Crown Network" or "Government Secure Network" (GSN) is a concept in Australian government where agencies are interconnected via secure links (MPLS, SD-WAN) through a government backbone.

- In WA, the **Shared Services Centre (SSC)** provides network connectivity services across agencies.
- Agencies connect via secure Wide Area Network (WAN) links to the government backbone.
- The `sharedservices.wa.gov.au` hosts act as cross-agency infrastructure.

**Ref ID: NETWORK-004** — Crown network / government backbone. Source: tenders.wa.gov.au (network procurement), wa.gov.au publications.

### 5.4 High-Risk Vulnerability Categories for Government

**1. Authentication Bypass on Citizen-Facing Portals (CRITICAL)**
- WA government runs dozens of citizen portals: driver licensing (transport.wa.gov.au), fines payment (justice.wa.gov.au), health records, student portals, licensing
- An auth bypass on any of these would expose PII of millions of WA residents
- Example: CVE-2024-0204 (MOVEit auth bypass) on health file transfer

**2. RCE on Domain Controllers (CRITICAL)**
- Windows DCs are the "keys to the kingdom" in any agency
- CVEs like CVE-2021-42287/CVE-2021-42278 (samAccountName spoofing → DC compromise)
- As of 2026, KEV still lists legacy CVEs like CVE-2008-4250 (MS08-067) — indicating unpatched legacy DCs remain a problem

**3. RCE on Perimeter / VPN Gateways (CRITICAL)**
- Citrix ADC, VPN concentrators are internet-facing by definition
- 5+ Citrix CVEs in KEV targeting these devices
- Network access from DMZ → Internal is the most common lateral movement path

**4. SQL Injection in Legacy Applications (HIGH)**
- Many WA government applications were built in the 2000s using .NET/SQL Server with SQLi vulnerability patterns
- Apache Struts (Communities case management) — CVE-2023-50164 (file upload RCE)

**5. Supply Chain via ITSM/RMM Tools (CRITICAL)**
- ScreenConnect and ManageEngine are remote management tools — compromise gives attackers the keys to manage all endpoints
- This is the attack chain in the "Supply Chain Attack — Finance" scenario

**Source:**
- ACSC Annual Cyber Threat Report 2023-24 (cyber.gov.au)
- ASD Threat Report
- CISA KEV prioritisation

## Assessment

This research confirms that **TriageMate's existing demo data is well-aligned with real WA government infrastructure patterns**. The synthetic hostname format (`per-PRD-{APP}{NUM}.{agency}.wa.gov.au`) is consistent with the documented standard and observed agency conventions.

### Key Findings

1. **Agency Coverage:** 23 WA government agencies/research entities identified with confirmed domains. The 8-10 agencies used in the existing CMDB and demo scenarios represent the core set of major departments.

2. **Enterprise Software:** 21 enterprise software systems identified. The demo data already covers the most critical ones (MOVEit, Citrix ADC, Confluence, ManageEngine, Exchange, SharePoint) with realistic CVE mappings.

3. **Hostname Patterns:** The `per-PRD-{ROLE}{NUM}.{dept}.wa.gov.au` pattern is robust. For synthetic generation: vary location codes (per, alb, ger, kal, bro), environment codes (DEV, TST, STG, UAT, PRD), and role suffixes from the 30+ confirmed codes.

4. **Network Zones:** 5 DMZ + 12 internal VLAN segments confirmed. Use network_zone strings matching the observed pattern: `{Agency}-{Zone}-{Subzone} (VLAN {num})`.

5. **CVE Landscape:** The KEV catalog confirms that CISA considers most of the CVEs in TriageMate's demo scenarios as "known exploited" — appropriate for simulation. The vast majority (65%+) have CVSS scores of 9.0+ and EPSS scores above 0.95.

### Recommendations for Synthetic Data Generation

**Assumption:** The strike team will generate 1,500-2,000 hostnames with associated vulnerability findings.

1. **Agency spread:** Distribute hosts across at least 12-15 agencies, weighted by size (WA Health, Education, Finance, Transport = higher count).
2. **Hostname diversity:** Use the full range of 30+ role codes, mix per/regional locations, vary environment codes (not all PRD).
3. **Network zones:** Map each host to the appropriate DMZ (if internet-facing) or internal VLAN per agency pattern.
4. **Data classification:** Map per WAICP: OFFICIAL (default), OFFICIAL Sensitive (health records, child protection, court files, police operations).
5. **CVE distribution:** Heavily weight toward KEV-listed CVEs with EPSS > 0.90 for realism. Include some low-severity hygiene findings (CVSS 3-5, EPSS < 0.1) for contrast.
6. **OS mix:** 70% Windows Server, 25% Ubuntu/RHEL, 5% legacy (Solaris, older Windows) per government patterns.

**Assumption:** The agency-specific subdomains (health.wa.gov.au, transport.wa.gov.au, etc.) all resolve to valid WA government infrastructure. For education, note the `.wa.edu.au` TLD is used instead of `.wa.gov.au`.
