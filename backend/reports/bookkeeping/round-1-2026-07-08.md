### ROADMAP.md vs ml_inventory.md — ROC-AUC and feature dimensions

Both files are marked CURRENT but contradict each other:

| Metric | ROADMAP.md | ml_inventory.md | Actual (verified from NPZ) |
|--------|-----------|-----------------|---------------------------|
| ROC-AUC | **0.9459** (4 refs: lines 81, 119, 128, 172) | **0.9409** (2 refs: lines 134, 170) | Unknown — value is computed at runtime by `train_xgboost.py` |
| NPZ features | **419** (35 tabular + 384 SBERT) (lines 69, 128, 172) | **420** (36 tabular + 384 SBERT) (lines 133, 139, 164) | **419** — `X.shape = (253568, 419)`, `columns.shape = (35,)` confirmed |
| Tabular count | **35** (lines 69, 119, 128, 172) | **36** (lines 133, 139, 141) | **35** — training pipeline produces 35, predictor expects 35 |

**Root cause:** The graphify generator (`generators/ml_inventory.py`) has these values **hardcoded** as string constants:
- Line 227: `"| Features (NPZ) | 420 (36 tabular + 384 SBERT) |\n"`
- Line 228: `"| ROC-AUC | 0.9409 |\n"`
- Line 233: `"| Input: 420 total dimensions = 36 tabular + 384 SBERT embedding\n"`
- Line 258-264: Dimension mismatch warning (now resolved)
- Line 267: `"ROC-AUC: 0.9409 (retrained on 253,568 samples, 2026-07-08)"`
- Line 289-290: `"⚠️ Dimension mismatch: model trained with 420 features, predictor sends 419"`

Every time `just graphify` runs, it overwrites `graphify_output/ml_inventory.md` with these stale hardcoded values, perpetuating the contradiction.

**Action needed (code fix, not .md fix):** Update `generators/ml_inventory.py` to:
- ROC-AUC 0.9409 → 0.9459 (consistent with ROADMAP)
- Features 420/36 → 419/35 (consistent with actual NPZ and ROADMAP)
- Remove or rewrite the "dimension mismatch" note (it's resolved)
