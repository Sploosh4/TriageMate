## 2. Model ↔ Predictor Dimension Match — FAIL (script error)

**Status: FAIL — but for the wrong reason.** The audit script itself is broken.

**What happened:** The audit script tried `from ml.xgboost_predictor import TABULAR_FEATURE_ORDER`, but **no such constant exists** in `ml/xgboost_predictor.py`. The tabular features are defined inline within the `predict()` function body (lines 128-166), not as a module-level exported constant.

**Actual dimension check (manual):**
| Component | Features | Status |
|---|---|---|
| Model (`xgboost_model.pkl`) | 419 | ✓ |
| Predictor (`xgboost_predictor.predict()`) | 35 tabular + 384 text = 419 | ✓ |
| NPZ training data (`X` shape) | (253568, 419) | ✓ |

The model, predictor, and training data are all in sync at **419 dimensions**. No actual dimension mismatch.

**The constant does exist in two other locations:**
- `tests/test_feature_parity.py:23` — `PREDICTOR_TABULAR_KEYS` (35-element list)
- `analysis/feature_parity_check.py:21` — `FEATURE_NAMES` (35-element list)

**P2 — Missing module-level constant:** `ml/xgboost_predictor.py` should export a `TABULAR_FEATURE_ORDER` constant (or similar) so audit scripts and downstream consumers don't need to reverse-engineer the feature order from the inline list in `predict()`.
