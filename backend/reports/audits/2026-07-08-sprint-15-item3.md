## 1. Full Test Suite

**Command:** `python3 -m pytest tests/ -v --tb=short`
**Result:** 143 passed, **1 failed**

**Failed test:** `test_full_pipeline_ingest` in `tests/test_integration.py:101`
```
AssertionError: Missing substitutionBlock
assert 'substitutionBlock' in {'summaryParagraphs': [...], 'missionPrevalence': [...],
                                'mitreTechniques': [], 'textConflict': False, ...}
```

The `case_view` dict returned does not contain the `substitutionBlock` key. This is because the `CaseViewData` model's `substitution_block` field is `Optional[SubstitutionBlock]` and defaults to `None`, and the response has `response_model_exclude_none=True` set on the route decorator. When `epss_sub["substituted"]` is `False`, the `substitutionBlock` is `None` and gets excluded by Pydantic's `exclude_none=True`.

**Root cause:** The test expects `substitutionBlock` unconditionally, but it is only present when EPSS substitution occurs. The test needs to account for cases where substitution is not triggered.

**Finding:** 1 test regression against the 144 baseline. Needs test fix or logic change.

## 2. Stress DB Round-Trip

**Command:** Inline Python script using `analysis.stress_db`

**Initial run:** Row count assertion passed (3 rows) ✓
```
Stress DB round-trip OK: 3 results
```

**But:** The test script from the prompt passes `json.dumps(trace_dict)` to `insert_result()`, which declares its parameter as `trace: dict` and internally calls `json.dumps(trace)`. This double-encodes the trace:
- Stored value: `"\"{\\\"tier_0\\\": ...}"` (a JSON string whose value is another JSON string)
- Expected: `"{\"tier_0\": ...}"` (a JSON string whose value is an object)

**Finding:** The audit test script's API usage is incorrect. When the trace dict is passed directly (not pre-serialized), everything works correctly:
```
Stress DB round-trip OK: 3 results, trace correctly stored as JSON dict
```

**Recommendation:** Fix the test script to pass `trace` as a `dict`, not `json.dumps(trace)`.
