# Retained database adoption companion

The `retained_runner` directory name identifies a frozen historical compatibility profile, not a current CI host or application deployment. It remains intact pending the database standards discussion. This companion preserves the exact archived backend `public` revision 058 found alongside the historical v113 evidence installation. It does not restore retired product routes, migration startup or fresh-install requirements. Ordinary empty, synthetic and runner installations keep their existing baseline artifact ledger; only adoption of this exact combined layout records the additional `retained-runner/` artifact hashes.

The contracts were constructed independently from archived Alembic 001–058 at `a8d3afcac467e01b0dea894b93cdfba8a1b93f95`, the byte-identical migration tree at `0d11c14a81ef4e94f4788caedb1d389ba32ef5c6`, and the previously trusted synthetic runner construction. The archived schema construction creates `public AUTHORIZATION triagemate` before those migrations. `construction.json` records source hashes and the exact independently composed predecessor signature. Observed historical metadata was used only for comparison, never to construct a trusted contract.

These source revisions identify the original construction; obsolete Git history and recovery tags have been removed. The checked-in contracts, manifests and synthetic archive remain the test/runtime inputs. Their reference bytes and hashes are preserved; verification does not retrieve the historical migration tree from Git.

The three legacy non-login roles and their surviving global grants come from `77d44c2bb7e2ceb61fbe4c8864ea49246d239491:backend/tests/conftest.py`. Retention-role memberships belong only to the provisioning administrator. Their attributes, memberships and settings are verified separately because the original baseline catalogue covers `tm_*` role attributes. The whole catalogue still verifies every non-system schema object and object grant; no public objects or grants are ignored. Revision metadata must contain exactly `058`.

The original and restored contracts differ only in the four established PostgreSQL deparser changes: one constraint, one policy and two completeness-view rules. Controlled full-database archives expect initdb's empty `public` namespace to remain present and restore its ownership and ACLs. An explicit `--schema=public` inspection dump instead emits `CREATE SCHEMA public`; it is not a restore artifact for this workflow. Restore preparation requires a different isolated cluster, an empty database, the exact provisioning owner and no preexisting legacy roles. Source objects are never dropped or reset.

The synthetic fixture under `backend/tests/fixtures/retained_runner/` combines the independently rebuilt public schema with data from the trusted synthetic v113 runner fixture. Regression coverage exercises complete backup/restore/adoption, stored legacy data and sequence preservation, role and schema drift, public revision changes, predecessor signature changes and missing companion ledger entries. Future revisions must provide an exact combined post-change contract and retain the companion ledger. Production adoption still requires unchanged evidence, an independently verified restore and full source attribution verification.
