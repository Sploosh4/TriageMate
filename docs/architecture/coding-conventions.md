# TriageMate coding conventions

These conventions govern current application work. Product scope, evidence provenance, source-validation rules and database authority take precedence over style changes. Do not rewrite immutable historical migration/source bytes or format third-party vendor artifacts. The selected rules draw on [PEP 8](https://peps.python.org/pep-0008/), the [Google Python guide](https://google.github.io/styleguide/pyguide.html), the [Google TypeScript guide](https://google.github.io/styleguide/tsguide.html) and [React component design](https://react.dev/learn/thinking-in-react); they are a project selection, not blanket compliance with every external guide.

## Python

Use descriptive `snake_case` modules and functions, `PascalCase` classes and uppercase constants. Ruff is the only Python formatter. Its configured E4/E7/E9/F rules reject invalid imports, statements and undefined/unused names while avoiding a second incompatible formatting rule set. Prefer explicit package imports, standard-library imports before third-party imports and then application imports. Keep import-time code free of service startup, collection and writes. Command modules use a guarded `main()`.

Annotate new public interfaces and altered contracts. Mypy checks the shared configuration/database packages strictly as the initial adoption boundary. Existing collectors, assessments, operations and application services retain behavioural checks and enter typing scope when their interfaces are migrated; this is a visible adoption boundary, not a blanket ignore of type errors. Tests and third-party artifacts are outside this initial static type target. Do not introduce unexplained `Any`, blanket error ignores or stub installation at check time.

Catch specific failures at the layer that can handle them, preserve the original failure cause internally and return an actionable public error without secrets. Validate untrusted source values at parsing/API/configuration boundaries; do not manufacture missing facts. Database functions must state transaction ownership. Connection acquisition does not implicitly commit, install or elevate roles; callers close their connections and explicitly own commit/rollback.

## TypeScript and React

Keep strict TypeScript checking. ESLint's JavaScript/TypeScript recommended rules and React Hooks ordering/dependency rules provide lint checks; Prettier owns frontend formatting, with single quotes, trailing commas and a 100-column target. The formatter takes precedence over external formatting advice. Compiler-specific React optimisation rules are not enabled while the application does not use that compiler.

Use `PascalCase.tsx` for components, `usePascalCase.ts` for custom Hooks and descriptive `camelCase.ts` for other modules. Existing public entry points may retain their names through a documented transition. Prefer named exports for reusable interfaces and components; configuration and framework-required default exports are exceptions. Model UI state explicitly, keep display types close to their components and avoid duplicating state that can be computed from existing inputs. Never hide unknown evidence or change source semantics to simplify rendering.

## Module responsibilities

A module owns one coherent responsibility; neither one function nor one class per file is required. Split when responsibilities change independently, dependencies diverge or interfaces become hard to understand. Length is a review signal, not a forced line limit. Avoid vague `utils`, `helpers` and `manager` buckets. Shared modules need actual shared consumers and a defined interface.

Shared configuration and database packages must not depend on UI application modules or collectors. Collection owns transport and original-response capture; parsing owns source validation and source facts; assessment owns evidence-backed matching; persistence owns transactions and restricted writes; explicit migrations own schema changes. Operations orchestrates those interfaces and their cancellation/checkpoint lifecycle. API/UI consumes application interfaces and presents evidence. Break dependency cycles by clarifying responsibility, not by adding dynamic imports or global mutable service registries.

The evidence pipeline keeps validated snapshot contracts at its root. `standalone/evidence_pipeline/parsing/` owns Microsoft device, software, antivirus, recommendation, vulnerability, update-status and source-time normalization, public feed/discovery parsing and source-record projections. It accepts source snapshots or fields and returns source facts; it does not acquire connections, commit transactions, call providers or choose device actions. Callers import the defining parser module directly, for example `from standalone.evidence_pipeline.parsing.devices import normalize_devices`. Parser tests currently remain in the corresponding `standalone/evidence_pipeline/test_*.py` files so their existing full-gate discovery is preserved. Public parser modules preserve source-specific contracts and bounded streaming readers. The shared publication-date interpretation belongs beside the publication parser, not in collection selection. A static dependency check rejects parser imports of provider I/O and application database modules; bounded local spill storage and exact source encoding are explicit foundation dependencies. `standalone/evidence_pipeline/source_json.py` supplies exact-number encoding to Microsoft adapters and public projections, preserving decimal values without routing public parsers through a Microsoft adapter package. `standalone/evidence_pipeline/collection/` owns explicit provider requests, collection pacing, discovery selection and durable source bundles. It retains replay readers alongside the corresponding bundle writers. Collection commands at their established root paths are small guarded launchers into this package; reusable callers import the package implementation. `parsing.osv_query` owns the retained OSV query/page contract, while the deferred collection refusal remains in `collection.osv_query`. `PublicDownload` is a source-response contract in `contracts.py`, so parsers do not import transport to recognize retained responses. `assessment/` owns product/version matching, applicability conditions and publisher release correspondence. It consumes validated facts and source parsers without importing collection or application persistence. The same static dependency check enforces that direction; the native inventory manifest validator is an explicit shared fact boundary. `persistence/` owns transactional evidence writers, source authorization, source-attribution reconstruction, bounded stored-claim lookup and committed repository-membership publication. Command modules continue to orchestrate registration and commits through these interfaces. Schema installation, exact catalogue verification, backup/adoption and future revision bookkeeping belong to `backend/database/`, not collector startup. Public snapshot validation and fixed public URL derivation live in `parsing.public_snapshot` and `parsing.public_routes`; saved-source attribution does not import HTTP transport to validate a route. Association decoding belongs to `parsing.exposure` and is shared by bundle validation and persistence. Repository completion is an explicit local replay exception: persistence publication uses the collection package’s saved-bundle readers with `replay_only=True` to verify pinned membership and committed receipts. These readers remain alongside their writers to preserve one bundle format and validation implementation; this exception does not permit network acquisition or new bundle creation during publication.

Within a Python file, place its purpose, imports, constants, public types and cohesive functions/classes before its executable entry point. Keep related private helpers near their callers when it improves readability. Define public entry points deliberately and avoid importing private helpers from unrelated packages. For example, connection acquisition belongs in `backend/database/connections.py`; permission installation belongs in explicit provisioning code and must never occur simply because a connection module is imported.

## Tests and changes

Keep `test_*.py` files in the existing corresponding Python test directory or beside the implementation until the package migration records their destination. Keep browser `*.spec.ts` tests under the UI test directory. Distinguish unit, isolated database integration, retained-evidence integrity and browser coverage in names and receipts. A cached fixture returned twice tests duplicate ingestion; only reading a durable saved bundle through its production reader proves durable replay. Published Windows identity contracts are parameterised in `test_published_component_identity.py` and `test_published_appx_identity.py`. Shared assertions preserve every reference row and each family’s original input fields, negative cases and alias exclusions; bundle/framework distinctions and observed-versus-reference version checks remain explicit. The common recognizer permission-drift case runs once, while every distinct reference artifact has its own metadata-removal check.

For behaviour changes, test the useful behaviour and the relevant failure boundary. Preserve malformed-source, conflicting-identity, permission, corruption, cancellation, retry/restart and offline-replay cases. A test consolidation must record its equivalent retained coverage or retired requirement in the canonical issue. Assertions must reject representative incorrect behaviour, not merely check that an output string looks plausible.

The same configured commands must run locally, in hooks and in the final gate. Dependency changes are pinned and reviewed with lockfile provenance; installation is separate from validation. Run focused checks while implementing and the complete applicable container/API/UI/database gate at the whole-task boundary. Generated data, private lab evidence, immutable historical artifacts and third-party vendor code are not formatter targets. Whole-task publication and main-integration authority remain governed by the project instructions.
