# Retained input inventory

This filename is retained for generated catalogue links. It describes input boundaries, not an active sprint plan or evidence that a fresh container installation has configured sources.

Supported implementation families include Entra devices; Intune managed devices, detected applications/associations and the verified expedited-policy report; Defender machines, findings/catalogue, missing-KB, antivirus, assessment/change and recommendation inputs; and public current FIRST EPSS, CISA KEV, selected NVD CVE/CVSS, CVE/CISA repository records, MSRC and Update Catalog routes. Each deployment must configure authorized source instances and verify entitlement/scope. Registry metadata does not activate collection.

Windows read-only registry/Appx inventory is a retained source contract. The Linux application container cannot collect another machine's local registry; an authorized source-side export is required. Intune policy reports do not establish exact installed/needed KB applicability. Preserve identity, observation dates, provider semantics and unknown outcomes.

Deferred inputs and recovery boundaries are in [the restoration guide](../guides/DEFERRED_INPUT_RESTORATION.md). Exact API/source fields remain in [the generated catalogue](MICROSOFT_API_SCHEMA_MAPPING.md), [mapping CSV](MICROSOFT_API_SCHEMA_MAPPING.csv) and [Microsoft inventory CSV](MICROSOFT_INFORMATION_INPUTS.csv). Public field research remains in [source research](MICROSOFT_SCORING_INPUTS_RESEARCH.md). These are contract references, not production-readiness claims.
