# Microsoft source semantics and public-source research

This retains dated source and licensing research, not a deployment architecture or fresh entitlement claim. The [current Microsoft tool comparison](../research/MICROSOFT_COLLECTORS.md) and [public feed comparison](../research/PUBLIC_FEEDS.md) guide the next experiments.

Microsoft inputs can provide technical evidence for managed devices, installed software, vulnerability assessments, update state, endpoint security and identity context. They do not establish service impact, importance, ownership, remediation deadlines or exceptions. Group names and assignments do not prove those facts. Unsupported values remain unknown; custom combined risk scoring is outside scope.

Intune inventory and deployment state, Defender findings and recommendations, and Entra identity observations have different scopes, observation times and licensing/permission requirements. A deployment report does not prove exact KB installation or applicability. Activity does not prove exploitation. The exact source mapping remains in [the generated catalogue](MICROSOFT_API_SCHEMA_MAPPING.md).

## Identity and interpretation limits

A package name is not a generic alias for a product. Microsoft's [Edge known issues](https://learn.microsoft.com/en-us/deployedge/microsoft-edge-known-issues) distinguishes `Microsoft.MicrosoftEdge.Stable`, a browser host package, from the browser itself. Its independently updated version cannot stand in for the installed Edge Chromium browser version in CVE/CPE matching.

Version normalization must be source-specific. Broadcom's [VMSA-2025-0015.1](https://support.broadcom.com/web/ecx/support-content-notification/-/external/content/SecurityAdvisories/0/36149) uses three/four-component VMware Tools versions, but does not justify arbitrary product aliases or version normalization elsewhere. Preserve affected-version conditions and unsupported environmental prerequisites as unknown.

MSRC publication discovery must retain exact publication identifiers and revision/release dates. The [official API schema](https://github.com/microsoft/MSRC-Microsoft-Security-Updates-API/blob/main/docs/swagger.json) documents `/updates` and CVRF links. Do not assume all publication IDs are `YYYY-Mmm` or that a revision timestamp proves a publication period. Source completeness and stored membership need independent verification.

## Fixture and provenance rules

Use explicitly synthetic fixtures for missing fields, ambiguous joins, pagination, permission failures, source dates, conflicting values and replay. Synthetic verification does not prove actual deployment coverage. Retain source URL, original bytes/hash, retrieval/observation dates, scope and transformations for public inputs; private operator payloads stay outside Git.

Microsoft Learn establishes field meaning rather than blanket redistribution rights. Developer Program services are for development/testing; tenant-bound sandbox responses are not automatically public datasets. Graph OpenAPI metadata has its own MIT license. See [Developer Program terms](https://learn.microsoft.com/en-us/office/developer-program/terms-and-conditions), [Learn terms](https://learn.microsoft.com/en-us/legal/termsofuse) and [Graph metadata license](https://github.com/microsoftgraph/msgraph-metadata/blob/master/LICENSE).
