## 2. Tier 2 — LLM Query Coverage

### When Tier 2 is called
**Not for all vulnerabilities.** Two gates determine who reaches the LLM:

1. **Tier 0 gate:** Must be `"escalated"` — very-critical auto-resolves (KEV + high CVSS + internet-facing) and very-low auto-resolves (CVSS < 4, EPSS < 0.1, not KEV) skip entirely
2. **Tier 1 gate:** XGBoost must route as `"escalated"` — confident predictions with moderate scores also skip

Result: Tier 2 handles only the most ambiguous/high-signal cases.

### What the LLM outputs
The LLM receives the CVE description as input and produces a **conflict assessment**, NOT a description:

```json
{
  "text_conflict": true/false,
  "conflict_note": "Plain-English explanation (max 300 chars)",
  "rag_result": "UNCERTAIN | CONFIRMED | NOT_NEEDED",
  "resolution": "Resolution recommendation (max 500 chars)",
  "confidence": 0.0-1.0,
  "score_adjustment": -20 to +20
}
```

Descriptions come from NVD enrichment upstream, not from the LLM.

### Testing gap
Tier 2 has NOT been directly tested. The only pipeline integration test (`test_fuzzed_ingest.py`) mocks `evaluate_tier_2` with `AsyncMock`. No unit tests exist for:
- `call_openai()`, `call_anthropic()`, `call_together()`
- The fallback chain (KNOWN_CONFLICTS → neutral default)
- The retry/backoff logic
- The cost tracking accumulators

### Provider fallback chain
```
Primary env var → Backup env var (if configured) → KNOWN_CONFLICTS dict (3 CVEs) → neutral default (confidence 0.30)
```
