# Bundled frontend notices

The application redistributes React, React DOM, CodeMirror and their runtime dependencies in compiled JavaScript. Their MIT copyright and license texts must accompany that distribution. [Generated notices](FrontendThirdPartyNotices.txt) include the locked runtime dependency closure, package versions, npm source archives and lockfile integrity values. The build copies the same text to `ui-engine/dist/third-party-notices.txt`; FastAPI serves it at `/third-party-notices.txt`. The application container therefore retains these notices even though it does not contain frontend `node_modules`.

`npm --prefix ui-engine run build` generates notices after Vite builds the assets. It reads installed package metadata and complete license files without downloading anything. Required dependencies and peer dependencies must resolve from the npm lock. Missing packages, mismatched installed versions, unreviewed package sources, missing or incomplete license files and licenses outside the reviewed MIT policy fail the build with an actionable error. This policy describes the current dependency set; a new license needs explicit review and a generator update rather than being silently omitted.

After an intentional frontend dependency update, run `npm ci` in `ui-engine`, then `npm run notices:update` there and review the generated source/version/license changes. `npm run test:notices` checks deterministic output, transitive/peer inclusion, failure paths and agreement with the checked-in notices. The copied license texts remain verbatim, including original copyright lines and line endings; only the surrounding inventory is generated. Build-time development dependencies are not included because they are not shipped in the frontend assets. These notices do not replace the separately retained [SQL parser notices](ParserThirdPartyNotices.md) or source-data licenses.
